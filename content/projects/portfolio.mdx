## Bối cảnh và bài toán
Hầu hết các trang portfolio lập trình viên hiện nay rơi vào hai thái cực: hoặc quá đơn giản như một bản CV tĩnh, hoặc lạm dụng animation 3D và màu sắc sặc sỡ làm giảm trải nghiệm đọc và tốc độ tải trang.
Bài toán đặt ra là xây dựng một trang web cá nhân vừa thể hiện được tư duy thiết kế tối giản, sạch sẽ theo phong cách Engineering Notebook, vừa chứng minh năng lực full-stack qua các tính năng thực tế: cơ sở dữ liệu quan hệ, xác thực OAuth, rate limit, kiểm thử tự động và đo lường hiệu năng.

## Mục tiêu và ràng buộc
- **Mục tiêu kỹ thuật:**
  - First Load JS của trang chủ phải luôn dưới 150 kB.
  - Điểm Accessibility và SEO đạt 100 điểm theo tiêu chuẩn Google Lighthouse.
  - Hỗ trợ chế độ Dark/Light với cơ chế triệt tiêu hoàn toàn hiện tượng nháy trắng (Zero Flash Theme).
- **Ràng buộc hệ thống:**
  - Hoạt động ổn định trên hạ tầng Serverless miễn phí (Vercel, Supabase, Upstash Redis).
  - Không sử dụng thư viện UI bên ngoài; toàn bộ Primitive UI phải được viết tay theo chuẩn WAI-ARIA.

## Kiến trúc giải pháp
Ứng dụng được kiến trúc theo mô hình Serverless Jamstack mở rộng:
- **Presentation Layer:** React Server Components (RSC) kết hợp Next.js 14 App Router để giảm tối đa kích thước bundle client.
- **Data Mutation Layer:** Server Actions xử lý các thao tác ghi (Guestbook, Contact) với cơ chế Optimistic UI.
- **Persistence Tier:** Supabase PostgreSQL quản lý dữ liệu qua Drizzle ORM type-safe, Upstash Redis đảm nhiệm caching và rate-limiting.

## Quyết định kỹ thuật và trade-off
- **Drizzle ORM thay vì Prisma:** Drizzle có dung lượng bundle nhẹ hơn, biên dịch trực tiếp sang câu truy vấn SQL thuần túy và không cần binary engine chạy ngầm, rất tối ưu cho môi trường Vercel Serverless Functions.
- **Hệ thống Design Tokens CSS tự viết:** Thay vì dùng shadcn/ui nguyên mẫu, dự án tự xây dựng các thành phần UI để kiểm soát 100% kích thước mã nguồn và khả năng tùy biến màu sắc 3 lớp.

## Thách thức và cách giải quyết
- **Hiện tượng Flash of Unstyled Theme (FOUC):** Khi tải lại trang ở chế độ Dark, trình duyệt thường chớp nền trắng trước khi React hydrate xong.
  - *Giải pháp:* Viết một đoạn script inline đồng bộ chèn thẳng vào thẻ `<head>` để đọc `localStorage` và áp dụng class `dark` lên thẻ `<html>` ngay trước khi DOM được vẽ.
- **Rate Limit trên GitHub API:**
  - *Giải pháp:* Xây dựng Route Handler `/api/telemetry` kết hợp Incremental Static Regeneration (ISR) với chu kỳ 3600 giây, kèm cơ chế fallback an toàn.

## Kết quả và bài học
- Hệ thống hoàn thành vượt chỉ tiêu kỹ thuật: First Load JS chỉ 94.1 kB (thấp hơn nhiều so với hạn mức 150 kB).
- Toàn bộ 16 bài kiểm thử đơn vị đều vượt qua 100%.
- Bài học rút ra: Thiết kế kiến trúc phân tầng rõ ràng ngay từ đầu giúp việc mở rộng tính năng và bảo trì mã nguồn diễn ra nhanh chóng, hạn chế tối đa lỗi hồi quy.
